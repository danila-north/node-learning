# Часть 1. JavaScript

## this
**Зачем:** чтобы один метод работал с разными объектами.
**Правило:** `this` — это то, что стоит **перед точкой** при вызове.

```js
const user = { name: "Данила", greet() { console.log(this.name); } };
user.greet(); // Данила — перед точкой user

const fn = user.greet;
fn(); // undefined — точки нет, this потерялся
```

## Стрелочные функции и this
**Зачем:** у стрелки нет своего `this`, она берёт его снаружи. Удобно в колбэках внутри методов.
**Правило:** для методов объекта — обычная функция, для колбэков внутри методов — стрелка.

```js
const timer = {
  name: "Таймер",
  start() {
    setTimeout(() => console.log(this.name), 1000); // Таймер
  },
};
```

## Прототип
**Зачем:** общее хранилище методов, чтобы не копировать их в каждый объект.
**Цепочка прототипов:** нет свойства в объекте → JS ищет в прототипе → нигде нет → `undefined`.

```js
const obj = { a: 1 };
obj.a;        // 1 — своё свойство
obj.toString; // нашлось в прототипе
obj.xyz;      // undefined — нет нигде
```

## super
**Зачем:** попросить родителя выполнить свою часть конструктора, чтобы не копировать его код.
**Правило:** вызывать первой строкой, до любого `this`.

```js
class User {
  constructor(name) { this.name = name; }
}
class Admin extends User {
  constructor(name, role) {
    super(name);      // User записывает имя
    this.role = role; // Admin дописывает роль
  }
}
```

## Замыкание
**Зачем:** функция помнит переменные снаружи, где была создана. Так делают приватные данные.

```js
function createCounter() {
  let count = 0;
  return () => ++count;
}
const counter = createCounter();
counter(); // 1
counter(); // 2 — count помнится
```

## Event loop
**Порядок:** синхронный код → микрозадачи (промисы, `.then`, `await`) → макрозадачи (`setTimeout`).

```js
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// A D C B
```

**Как это работает:**
- JS однопоточный: выполняет одну задачу за раз через **стек вызовов**.
- Долгие операции (запросы, таймеры, файлы) отдаются среде — браузеру или Node.js. Когда операция готова, её колбэк встаёт в очередь.
- Очередей две: **микрозадачи** (промисы, `await`) и **макрозадачи** (`setTimeout`, `setInterval`, события).
- Цикл: стек пуст → выполнить **все** микрозадачи → взять **одну** макрозадачу → снова все микрозадачи → ...

## const и let
- `let` — переменную можно перезаписать: `body += chunk`
- `const` — перезаписать нельзя, но **содержимое объекта менять можно**

```js
const user = { name: "Данила" };
user.name = "Петя"; // можно — меняем содержимое
user = {};          // ошибка — перезапись
```

## Falsy
**Шесть значений, которые в условии дают false:**
`false`, `0`, `""`, `null`, `undefined`, `NaN`. Всё остальное — truthy, даже `[]` и `{}`.

- `!x` — «если x falsy» → `if (!note)` = «если заметка не нашлась»
- `a || b` — «возьми a, а если оно falsy — b» → `process.env.PORT || 3000`

## Методы массивов (самое нужное)
| Метод | Возвращает | Пример |
|---|---|---|
| `find` | **один** элемент или `undefined` | `notes.find(n => n.id === id)` |
| `filter` | **новый массив** подходящих | `notes.filter(n => n.id !== id)` |
| `map` | **новый массив** преобразованных | `notes.map(n => n.id)` |
| `some` / `every` | `true` / `false` | `notes.some(n => !n.text)` |
| `reduce` | **одно значение** | `arr.reduce((sum, x) => sum + x, 0)` |

⚠️ `find` возвращает **ссылку** на объект из массива, а не копию. Поменял `note.text` — поменялось и в массиве.

## Set и Map
- **Set** — набор без повторов. Убрать дубли: `[...new Set(arr)]`
- **Map** — словарь «ключ → значение»: `set` положить, `get` достать, `has` проверить.

```js
[...new Set([1, 1, 2])]; // [1, 2]

const stock = new Map();
stock.set("mouse", 20);
stock.get("mouse"); // 20
```

## JSON
- `JSON.stringify(obj)` → **строка** (string-ify = сделать строкой). Чтобы отправить или сохранить.
- `JSON.stringify(obj, null, 2)` → строка **с отступами** (красиво для файла).
- `JSON.parse(str)` → **объект** (parse = разобрать). Кривой JSON ломает программу — оборачивать в `try/catch`.

## Шаблонные строки
Только в **обратных кавычках** `` ` `` (клавиша Ё в английской раскладке). Переменная — внутри `${}`.

```js
const name = "Данила";
`Привет, ${name}!`  // Привет, Данила!
"Привет, ${name}!"  // Привет, ${name}! — в обычных кавычках не работает
```

## Деструктуризация
**Слева** — новые переменные, **справа** — откуда берём.

```js
const { price: cost, discount = 0 } = product; // переименование и значение по умолчанию
const [first, second] = arr;
```

## Spread и rest
- **Spread** (справа от `=`) — высыпать: `[...a, ...b]`, `{ ...obj }`, `Math.max(...arr)`
- **Rest** (слева от `=`) — собрать остаток: `const [main, ...rest] = arr`
- **Что позже — то и выигрывает:** `{ ...a, x: 5 }` → `x` будет 5

## Копирование
- `b = a` → одно и то же под двумя именами
- `{ ...a }` / `[...a]` → поверхностная копия: вложенные объекты общие
- `structuredClone(a)` → глубокая копия: всё отдельно

## Промис
**Зачем:** обещание, что результат появится позже — успех (`resolve`) или ошибка (`reject`).
**Состояния:** pending → fulfilled или rejected.

## await
**Зачем:** остановить функцию, пока промис не выполнится, и получить результат.
**Без await** в переменной будет сам промис, а не результат. `await` работает только внутри `async`-функции.

```js
const a = getProduct(1);       // промис (ещё не готов)
const b = await getProduct(1); // готовый товар
```

## Promise.all и родственники
- `all` — все сразу, параллельно. Упал один — падает всё.
- `allSettled` — ждёт всех, никогда не падает, пишет статус каждого.
- `race` — гонка: кто первый закончил.
- `any` — первый **успешный**.

**Правило:** задачи не зависят друг от друга → `Promise.all`. Зависят → `await` по очереди.

## Модули
- `export` — отдать функцию из файла
- `import { fn } from "./file.mjs"` — взять функцию из другого файла
- В пути **обязательно** расширение `.js` / `.mjs`
- В одном файле — один способ: либо `import/export`, либо `require/module.exports`

# Часть 2. Node.js и бэкенд

## Общая картина: что мы делаем

```
Клиент (приложение, сайт, curl)          Сервер (бэкенд) — это пишу я
        |                                        |
        |  DELETE /notes/5  ───────────────────► |  находит, удаляет из базы
        |                                        |
        | ◄──────────────────────  200 + JSON    |
```

- **Фронтенд** — то, что видит пользователь: кнопки, вёрстка.
- **Бэкенд** — принимает запросы, проверяет данные, работает с базой, отвечает.
- `notes.json` — временная **база данных** (потом будет PostgreSQL).
- **curl** — притворяется приложением и отправляет серверу запросы.
- Браузер в адресной строке умеет только **GET**. POST/PUT/DELETE — через curl (или JS на сайте).
- Посмотреть запросы любого сайта: **F12 → Сеть → XHR**.

## Node.js
Запускает JS **вне браузера**. На нём пишут серверы и работают с файлами.

## Сервер
```js
import http from "http";
import { readFile, writeFile } from "fs/promises";

const server = http.createServer(async (req, res) => {
  // вызывается на КАЖДЫЙ запрос
});

server.listen(3000, () => console.log("Сервер: http://localhost:3000"));
```

| | Что это | Что внутри |
|---|---|---|
| `req` (request) | **запрос** — что пришло от клиента | `req.url`, `req.method`, тело |
| `res` (response) | **ответ** — что мы отправляем | код, заголовки, тело |

Запомнить: re**q** — **q**uestion (вопрос от клиента), re**s** — **s**end (отправляем).

- `res.end(...)` — отправить ответ. **Ровно один раз** на запрос, и **всегда последним**.

## CRUD
| Действие | Метод | Пример | Успех |
|---|---|---|---|
| **C**reate — создать | POST | `POST /notes` | 201 |
| **R**ead — прочитать | GET | `GET /notes`, `GET /notes/2` | 200 |
| **U**pdate — изменить | PUT / PATCH | `PUT /notes/2` | 200 |
| **D**elete — удалить | DELETE | `DELETE /notes/2` | 200 |

**Условие маршрута** — адрес И метод:
```js
if (req.url.startsWith("/notes/") && req.method === "PUT") {
```

## Коды ответа
- **2xx — успех:** 200 ок, 201 создано, 204 успех без тела
- **4xx — ошибка клиента:** 400 кривые данные, 401 не залогинен, 403 нельзя, 404 не найдено
- **5xx — ошибка сервера:** 500 у нас что-то сломалось

`res.statusCode = 404;` — ставить **до** `res.end`. Без него будет 200.

## Content-Type
Говорит, **что** в ответе и **как** читать. Без `charset` — кракозябры.
```js
res.setHeader("Content-Type", "text/plain; charset=utf-8");       // текст
res.setHeader("Content-Type", "application/json; charset=utf-8"); // JSON
```

## Полезные приёмы
```js
// id из адреса: "/notes/2" → ["", "notes", "2"] → 2
const id = Number(req.url.split("/")[2]);
// Number("abc") → NaN → find ничего не найдёт → 404

// тело запроса — приходит кусочками, собираем
let body = "";
for await (const chunk of req) {
  body += chunk;
}
const data = JSON.parse(body);

// новый id
const newId = Math.max(...notes.map(n => n.id)) + 1;

// удалить = оставить всех, КРОМЕ него
const remaining = notes.filter(n => n.id !== id);
```

## return после ошибки
```js
if (!note) {
  res.statusCode = 404;
  res.setHeader("Content-Type", "application/json; charset=utf-8");
  res.end(JSON.stringify({ error: "Заметка не найдена" }));
  return; // стоп, выходим из функции
}
```
Без `return` код пойдёт дальше и отправит второй ответ → Node упадёт.
Проверка с `return` лучше `if/else`, когда после неё ещё много кода.

## Порядок маршрута (на примере PUT)
Сначала пишу **план комментариями**, потом код под каждым шагом.

```js
} else if (req.url.startsWith("/notes/") && req.method === "PUT") {
  // 1. достать id из адреса
  const id = Number(req.url.split("/")[2]);

  // 2. собрать тело
  let body = "";
  for await (const chunk of req) body += chunk;
  const update = JSON.parse(body);

  // 3. проверить тело → 400
  if (!update.text) { /* 400 + ошибка */ return; }

  // 4. прочитать файл → массив
  const text = await readFile("week-03/notes.json", "utf-8");
  const loaded = JSON.parse(text);

  // 5. найти заметку → 404, если нет
  const note = loaded.find(n => n.id === id);
  if (!note) { /* 404 + ошибка */ return; }

  // 6. изменить
  note.text = update.text;

  // 7. сохранить — ВЕСЬ МАССИВ
  await writeFile("week-03/notes.json", JSON.stringify(loaded, null, 2));

  // 8. ответить — ОДНОЙ ЗАМЕТКОЙ
  res.setHeader("Content-Type", "application/json; charset=utf-8");
  res.end(JSON.stringify(note));
}
```

**Где что лежит:**
| Переменная | Что внутри |
|---|---|
| `body` | строка от клиента |
| `update` | объект от клиента `{ text: "..." }` |
| `text` | содержимое файла (строка) |
| `loaded` | **массив** всех заметок |
| `note` | **одна** найденная заметка |

**В файл — весь массив. Клиенту — одну заметку.**
**Сначала проверь вход (400), потом работай.**

## curl
```bash
# GET (-i показывает код и заголовки)
curl -i http://localhost:3000/notes

# POST
curl -i -X POST -H "Content-Type: application/json" -d '{"text":"привет"}' http://localhost:3000/notes

# PUT
curl -i -X PUT -H "Content-Type: application/json" -d '{"text":"новый"}' http://localhost:3000/notes/2

# DELETE
curl -i -X DELETE http://localhost:3000/notes/5
```
- `-X` — метод, `-H` — заголовок, `-d` — тело (данные)

## package.json и npm-скрипты
- **package.json** — паспорт проекта: название, команды и список библиотек.
  Создать: `npm init -y` (в корне проекта)
- **scripts** — короткие имена для длинных команд. Запуск: `npm run название`

```json
"scripts": {
  "notes": "node week-03/server.mjs",
  "dev": "node --watch --env-file=.env week-03/server.mjs"
}
```

- **--watch** — следит за файлами: сохранил файл → Node сам перезапускает сервер.
- `npm run dev` — общепринятое имя для запуска в режиме разработки.
- `echo` просто **печатает** текст, а не выполняет его.

## Переменные окружения (.env)
- **process.env** — объект с настройками, переданными программе снаружи.
  `const PORT = process.env.PORT || 3000;` → если PORT не передали, берётся 3000.
- **.env** — секреты (токены, пароли) и настройки, которые отличаются на разных компьютерах (порт, адрес базы).
  Формат: `PORT=5000` — без кавычек и пробелов.
- Node v22 читает его сам: `node --env-file=.env файл.mjs`
- Разово передать в терминале: `PORT=4000 npm run dev`
- **.gitignore** — что git НЕ отправляет на GitHub. Там **обязательно** `.env` и `node_modules`.
- **.env.example** — подсказка для других разработчиков, какие переменные нужны.
  Безопасные — со значением (`PORT=3000`), секреты — пустые (`SECRET_TOKEN=`). Его коммитим.

## Ошибки и отладка
- Читать строку **`Error:`**, серые строки `at ...` обычно можно пропустить.
  - `Cannot find module '...'` → неверный путь к файлу
  - `... is not defined` → переменной нет (опечатка или она внутри других `{ }`)
  - `Assignment to constant variable` → пытаюсь перезаписать `const`
- Красная волна в VS Code — ошибка уже видна, смотреть на неё.
- Белая точка на вкладке — файл **не сохранён** (Ctrl+S).
- Подсказки VS Code: **Ctrl+Space** — показать вручную.
- Node не подхватывает изменения сам — либо перезапуск (Ctrl+C), либо `--watch`.
