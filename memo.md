## this
**Зачем:** чтобы один метод работал с разными объектами.

```js
const user = { name: "Данила", greet() { console.log(this.name); } };
user.greet(); // Данила — перед точкой user

const fn = user.greet;
fn(); // undefined — точки нет, this потерялся
```

## Стрелочные функции и this
**Зачем:** у стрелки нет своего `this`, она берёт его снаружи. Удобно в колбэках внутри методов.
**Правило:** для методов объекта — обычная функция, для колбэков внутри методов — стрелка.

```js
const timer = {
  name: "Таймер",
  start() {
    setTimeout(() => console.log(this.name), 1000); // Таймер
  },
};
```

## Прототип
**Зачем:** общее хранилище методов, чтобы не копировать их в каждый объект.
**Цепочка прототипов:** нет свойства в объекте → JS ищет в прототипе → нигде нет → `undefined`.

```js
const obj = { a: 1 };
obj.a;        // 1 — своё свойство
obj.toString; // нашлось в прототипе
obj.xyz;      // undefined — нет нигде
```

## super
**Зачем:** попросить родителя выполнить свою часть конструктора, чтобы не копировать его код.
**Правило:** вызывать первой строкой, до любого `this`.

```js
class User {
  constructor(name) { this.name = name; }
}
class Admin extends User {
  constructor(name, role) {
    super(name);      // User записывает имя
    this.role = role; // Admin дописывает роль
  }
}
```

## Замыкание
**Зачем:** функция помнит переменные снаружи, где была создана. Так делают приватные данные.

```js
function createCounter() {
  let count = 0;
  return () => ++count;
}
const counter = createCounter();
counter(); // 1
counter(); // 2 — count помнится
```

## Event loop
**Порядок:** синхронный код → промисы (`.then`, `await`) → `setTimeout`.

```js
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// A D C B
```

## const и объекты
**Правило:** `const` запрещает перезаписать переменную, но не менять содержимое.

```js
const user = { name: "Данила" };
user.name = "Петя"; // можно — меняем содержимое
user = {};          // ошибка — перезапись
```

## Falsy
**Шесть значений, которые в условии дают false:**
`false`, `0`, `""`, `null`, `undefined`, `NaN`. Всё остальное — truthy, даже `[]` и `{}`.

## Set и Map
- **Set** — набор без повторов. Убрать дубли: `[...new Set(arr)]`
- **Map** — словарь «ключ → значение»: `set` положить, `get` достать, `has` проверить.

```js
[...new Set([1, 1, 2])]; // [1, 2]

const stock = new Map();
stock.set("mouse", 20);
stock.get("mouse"); // 20
```

## JSON
- `JSON.stringify(obj)` → **строка** (string-ify = сделать строкой). Чтобы отправить или сохранить.
- `JSON.parse(str)` → объект. Кривой JSON ломает программу — оборачивать в `try/catch`.

## Деструктуризация
**Слева** — новые переменные, **справа** — откуда берём.

```js
const { price: cost, discount = 0 } = product; // переименование и значение по умолчанию
const [first, second] = arr;
```

## Spread и rest
- **Spread** (справа от `=`) — высыпать: `[...a, ...b]`, `{ ...obj }`
- **Rest** (слева от `=`) — собрать остаток: `const [main, ...rest] = arr`
- **Что позже — то и выигрывает:** `{ ...a, x: 5 }` → `x` будет 5

## Копирование
- `b = a` → одно и то же под двумя именами
- `{ ...a }` / `[...a]` → поверхностная копия: вложенные объекты общие
- `structuredClone(a)` → глубокая копия: всё отдельно

## Промис
**Зачем:** обещание, что результат появится позже — успех (`resolve`) или ошибка (`reject`).
**Состояния:** pending → fulfilled или rejected.

## await
**Зачем:** остановить функцию, пока промис не выполнится, и получить результат.
**Без await** в переменной будет сам промис, а не результат.

```js
const a = getProduct(1);       // промис (ещё не готов)
const b = await getProduct(1); // готовый товар
```

## Promise.all и родственники
- `all` — все сразу, параллельно. Упал один — падает всё.
- `allSettled` — ждёт всех, никогда не падает, пишет статус каждого.
- `race` — гонка: кто первый закончил.
- `any` — первый **успешный**.

**Правило:** задачи не зависят друг от друга → `Promise.all`. Зависят → `await` по очереди.

Event Loop
JavaScript однопоточный: он выполняет код по одной задаче за раз через стек вызовов. Чтобы долгие операции — запросы, таймеры, чтение файлов — не блокировали программу, они отдаются среде: браузеру или Node.js. Когда операция готова, её колбэк попадает в очередь.

Очередей две: микрозадачи — промисы, .then, await — и макрозадачи — setTimeout, setInterval, события.

Event loop работает по циклу: когда синхронный код закончился и стек пуст, он сначала выполняет все микрозадачи, потом берёт одну макрозадачу — и снова все микрозадачи. Поэтому порядок: синхронный код → промисы → setTimeout. В браузере между этим ещё есть рендер.

Node js и HTTP

Node js - запускает JS вне браузера. На нем пишут серверы и работают с файлами.

Сервер

`http.createServer((req, res) => {...})` - функция вызывается на каждый запрос
`server.listen(3000)` - сервер ждет запросы на http:localhost:3000
`req` (request) - запрос, что прислали(req.url, req.method, тело)
`res` (response) - ответ, что отправляем(код, заголовки, тело)
`res.end(...)` - отправить ответ, ровно один раз на запрос

Методы CRUD
Create - создать, POST, POST /notes
Read - прочитать, GET, GET /notes GET /notes/2
Update - изменить, PUT/PATCH, PUT /notes/2
Delete - удалить, DELETE, DELETE /notes/2

Коды ответа
2хх - успех 200 - ок, 201 - создано
4хх - ошибка клиента: 400 - кривые данные, 404 - не найдено
5хх - ошибка сервера: 500 - у нас что-то сломалось

Content-Type
Говорит, Что в ответе и КАК читать. Без charset - кракозябры(случайные символы)
`res.setHeader("Content-Type", "text/plain; charset=utf-8` - текст
`res.setHeader("Content-Type", "application/json; charset=utf-8")` - JSON

Полезные приемы 
id из адреса: `Number(req.url.split("/")[2])` -> "notes/2" -> 2
req.url.starsWith("/notes/") - адрес начинается С
Number("abc") -> NaN -> find ничего не найдет -> 404
Тело запроса читаем по кусочкам:
`let body = ""; for await (const chunk of req) body += chunk;`
Новый id: `Math.max(...notes.map(n => n.id)) + 1`
Удалить: `notes.filter(n => n.id  !== id)` (Оставить всех кроме него)

Return после ошибки
`res.end(ошибка); return` - пустой return = "стоп, выходим из функции"
Без него код пойдет дальше и отправит второй ответ -> Node упадет

curl (проверка из терминала)
`curl -i http://localhost:3000/notes` - GET, -i показывает код и заголовки
`curl -i -X POST -H "Content-Type: application/json" -d '{"text":"привет"}' http://localhost:3000/notes`
`curl -i -X DELETE  http://localhost:3000/notes/5`

## package.json и npm-скрипты

- **package.json** — паспорт проекта: название, команды и список библиотек.
  Создать: `npm init -y` (в корне проекта)
- **scripts** — короткие имена для длинных команд, которые прописывает разработчик.
  Запуск: `npm run название`
  ```json
  "scripts": {
    "notes": "node week-03/server.mjs",
    "dev": "node --watch week-03/server.mjs"
  }
  ```
- **--watch** — следит за файлами: как только сохраняю файл, Node сам перезапускает сервер.
- `npm run dev` — общепринятое имя для запуска в режиме разработки.
- `echo` в терминале просто ПЕЧАТАЕТ текст, а не выполняет его.
- Ошибку читаю по строке `Error:` (например, `Cannot find module` = неверный путь к файлу).

## Переменные окружения (.env)

- **process.env** — объект с настройками, переданными программе снаружи.
  `const PORT = process.env.PORT || 3000;` → если PORT не передали (undefined), берётся 3000.
- **.env** — файл с секретами (токены, пароли) и настройками, которые отличаются
  на разных компьютерах (порт, адрес базы). Формат: `PORT=5000`, без кавычек и пробелов.
- Node v22 читает его сам: `node --env-file=.env файл.mjs`
- **.gitignore** — список того, что git НЕ отправляет на GitHub.
  Там ОБЯЗАТЕЛЬНО `.env` (и `node_modules`).
- **.env.example** — подсказка для других разработчиков: какие переменные нужны.
  Безопасные настройки со значением (`PORT=3000`), секреты пустые (`SECRET_TOKEN=`).
  Его коммитим.
- Шаблонная строка: `` `Порт: ${PORT}` `` — только в обратных кавычках (клавиша Ё).
